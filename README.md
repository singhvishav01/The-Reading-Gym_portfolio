# The Reading Gym

> *Make reading feel like a sport.*

A gamified, social reading tracker built with React Native and Supabase. Users join multiplayer **reading rooms** tied to specific books, track chapters like athletes log workouts, and compete against friends on live leaderboards — all designed around the core problem that people want to read more but don't finish books.

---

## The Problem

Finishing books is hard. There's no external accountability, no visible progress to others, and no moment of recognition when you do finish. The Reading Gym solves this by making reading inherently social and competitive — the same psychological loop that makes fitness apps like Strava work, applied to books.

---

## Core Features

### Reading Rooms
Every book has one shared room. Join a room and you see everyone else's current chapter in real time — powered by Supabase Realtime WebSocket subscriptions. The lightweight competitive pressure of seeing a friend three chapters ahead is often enough to make you open the book.

### Chapter Tracking + XP
Log chapters with a single tap. Each chapter awards **10 XP**, handled server-side by a PostgreSQL trigger so it can't be manipulated client-side. Finishing a book and passing the comprehension quiz awards a **+50 XP** bonus.

### Daily Streaks
Reading anything on consecutive days builds your streak. The client compares today's date against a `last_read_at` timestamp on the user record, applies the correct increment/reset logic, and persists both `last_read_at` and `streak_days` back to the database in a single update.

### AI Book Comprehension Quiz
When a user marks a book as finished, they must pass a 10-question quiz generated by **GPT-4o-mini** to confirm they actually read it. Rules designed to prevent cheating:
- 60-second timer for all 10 questions
- Minimising or backgrounding the app causes the timer to run at **double speed** (tracked via `AppState`)
- Must answer 7 of 10 correctly to pass

On passing, the user unlocks the ability to write a review and star rating.

### Book Detail Pages
Tapping any book opens a detail screen showing:
- Open Library metadata (description, publish year, genre subjects)
- Community rating pulled from the Open Library ratings API
- Average star rating from in-app reviews
- All current readers and their chapter positions
- All reviews left by users who completed the quiz

### Social Feed
A Twitter-style activity feed shows chapter milestones, room joins, reactions, and completions from across the community. Users can also post text + photo updates tagged to a specific book.

### Spoiler-Safe Chapter Reactions
Users can react to chapters with emoji reactions — but only chapters they've already reached. This prevents spoilers: if you're on chapter 8, you can't see what other readers reacted to in chapter 12.

### Friend System
Discover other readers by username, send friend requests, and see which books your friends are currently reading on the Discover screen.

## Architecture Decisions

**Server-side XP via Postgres triggers**
XP is calculated in a `AFTER INSERT OR UPDATE` trigger on `reading_progress`, not in application code. This means no client can award itself XP by crafting a direct API call — the database is the single source of truth.

```sql
create or replace function public.handle_progress_xp()
returns trigger as $$
declare
  chapter_diff integer;
  xp_to_add integer := 0;
begin
  chapter_diff := case when TG_OP = 'INSERT'
    then new.current_chapter
    else new.current_chapter - old.current_chapter
  end;

  if chapter_diff > 0 then xp_to_add := chapter_diff * 10; end if;
  if TG_OP = 'UPDATE' and new.is_completed and not old.is_completed
    then xp_to_add := xp_to_add + 50;
  end if;

  if xp_to_add > 0 then
    update public.users set xp = xp + xp_to_add where id = new.user_id;
  end if;

  return new;
end;
$$ language plpgsql;
```

**Supabase Realtime for live reading rooms**
Chapter updates subscribe via `supabase.channel()` on the `reading_progress` table. When any reader in the room updates their chapter, everyone else's leaderboard re-renders within ~200ms — no polling.

**One-room-per-book data model**
`reading_rooms` has a `UNIQUE` constraint on `book_id`. The room is created lazily on first access. This means you can never have fragmented communities for the same book — everyone who reads *Dune* is in the same room.

**Client-side streak logic with server timestamp**
Streaks are deliberately computed client-side to avoid a server-side cron job. The client reads `last_read_at` from the user record, compares it to today and yesterday in local time, then writes the result back. This trades strict accuracy (timezone edge cases around midnight) for zero infrastructure complexity.

**Quiz anti-cheat without a server**
The double-speed timer penalty is purely client-side — a determined cheater could bypass it. The design decision was that this is casual social pressure, not a high-stakes exam, so the friction is calibrated to deter lazy cheating (switching apps to look up answers) without over-engineering a surveillance system.

## Database Schema

```
users
  id, username, avatar_url, bio, interests,
  xp, streak_days, last_read_at, created_at

books
  id (Open Library work ID), title, author,
  cover_url, description, created_at

reading_rooms
  id, book_id (UNIQUE), created_at

reading_progress
  id, user_id, room_id, book_id,
  current_chapter, is_completed, status,
  updated_at
  UNIQUE(user_id, book_id)

chapter_reactions
  id, user_id, book_id, chapter_number,
  reaction_type, created_at
  UNIQUE(user_id, book_id, chapter_number, reaction_type)

feed_events
  id, user_id, event_type, book_id,
  metadata (jsonb), created_at

friendships
  id, requester_id, addressee_id, status, created_at

book_reviews
  id, user_id, book_id, rating (1-5),
  review_text, created_at
  UNIQUE(user_id, book_id)
```

## Getting Started

### Prerequisites
- Node.js 18+
- Expo CLI (`npm install -g expo-cli`)
- A [Supabase](https://supabase.com) project (free tier works)
- An [OpenAI](https://platform.openai.com) API key

### Setup

```bash
git clone https://github.com/singhvishav01/The-Reading-Gym_portfolio.git
cd The-Reading-Gym_portfolio
npm install
cp .env.example .env
# Fill in your keys in .env
```

### Database

Run each migration file in order in your Supabase SQL Editor:

```
supabase/migrations/001_initial.sql
supabase/migrations/002_add_completion.sql
supabase/migrations/003_add_posts.sql
supabase/migrations/004_add_streak_tracking.sql   # or use 006
supabase/migrations/005_add_reviews.sql
supabase/migrations/006_add_status_and_streaks.sql
```

Migration 006 is idempotent — it covers everything from 004 onward safely.

### Run

```bash
npx expo start
# Press 'i' for iOS simulator, 'a' for Android emulator, or scan QR with Expo Go
```

## Design System

The app uses a **black & gold** token system defined in `lib/constants.ts`. All colours, spacing, typography, and border radii are referenced by semantic name — no hardcoded hex values in component files.

| Token | Value | Usage |
|---|---|---|
| `Colors.bg` | `#0C0C0C` | Screen backgrounds |
| `Colors.surface` | `#181818` | Cards, modals |
| `Colors.accent` | `#C9A84C` | Buttons, borders, active states |
| `Colors.gold` | `#F0C040` | XP bars, streak counter |
| `Colors.text` | `#F7F3ED` | Primary text |
| `Colors.textMuted` | `rgba(247,243,237,0.45)` | Secondary text, timestamps |
